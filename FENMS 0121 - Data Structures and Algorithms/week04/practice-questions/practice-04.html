Implement the binary search algorithm that can work on a LinkedList object.

The LinkedList implementation is the same one from lectures and labs; however the get() method, [] overloading and iterators have been purposefully removed from it.

The binary_search() method is set up so it can access private members of the LinkedList class (head and size).

Answer:(penalty regime: 0 %)
Show solution
template <typename Data>
int binary_search(const LinkedList<Data>& list, const Data& key) {
    int low = 0;
    int high = list.size - 1;
    Node<Data>* start = list.head;   // node at index low

    while (low <= high) {
        int mid = low + (high - low) / 2;

        Node<Data>* cur = start;      // walk from low to mid
        for (int i = low; i < mid; ++i)
            cur = cur->next;

        if (cur->data == key)
            return mid;
        if (cur->data < key) {
            low = mid + 1;
            start = cur->next;
        } else {
            high = mid - 1;
        }
    }
    return -1;
}

A list has no random access, so reaching mid means walking node by node. Keeping a pointer to the node at low means each walk starts there instead of at head.

There are O(log n) comparisons, but the walking adds up to about n/2 + n/4 + … ≈ n steps, so the whole search is O(n). On a linked list, binary search is no faster than linear search.

Implement the bubble sort algorithm that can work on a LinkedList object.

The LinkedList implementation is the same one from lectures and labs; however the get() method, [] overloading and iterators have been purposefully removed from it.

The bubble_sort() method is set up so it can access private members of the LinkedList class (head and size).

Answer:(penalty regime: 0 %)
Show solution
template <typename Data>
void bubble_sort(LinkedList<Data>& list) {
    for (int i = 0; i < list.size; i++) {
        bool swapped = false;
        Node<Data>* cur = list.head;
        for (int j = 1; j < list.size - i; j++) {
            if (cur->next->data < cur->data) {
                swap(cur->data, cur->next->data);
                swapped = true;
            }
            cur = cur->next;
        }
        if (!swapped) break;
    }
}

This is the optimized bubble_sort() from Lab 04 with arr[j-1] and arr[j] replaced by cur and cur->next. Only the stored values are swapped, and the links between nodes stay as they are.

Question 3

Not complete
Marked out of 25.00

In software development, semantic versioning (numbers like 1.2.10 or 2.0.1) is used to indicate the state or progress of software releases.

A version typically consists of three numbers, in this order: major, minor, and patch numbers.
Example: 3.0.4 → 3 (major), 0 (minor), 4 (patch).

In the preloaded code, you have a basic struct Version for keeping track of version numbers. Your task is to implement overloads for all comparison operators (==, !=, <, >, <=, >=), and enable a direct comparison between two Version instances.

Versions are compared like this:
– First compare the major number.
– If major numbers are equal, compare minor.
– If those are also equal, compare patch.

Some examples:

2.0.1 > 1.10.5
1.4.0 > 1.3.20
1.1.4 > 1.1.3

Answer:(penalty regime: 0 %)
Show solution
struct Version {
    int major;
    int minor;
    int patch;

    Version(int _ma, int _mi, int _pa): major(_ma), minor(_mi), patch(_pa) {}

    friend bool operator==(const Version& a, const Version& b) {
        return a.major == b.major && a.minor == b.minor && a.patch == b.patch;
    }
    friend bool operator!=(const Version& a, const Version& b) {
        return !(a == b);
    }
    friend bool operator<(const Version& a, const Version& b) {
        if (a.major != b.major) return a.major < b.major;
        if (a.minor != b.minor) return a.minor < b.minor;
        return a.patch < b.patch;
    }
    friend bool operator>(const Version& a, const Version& b) {
        return b < a;
    }
    friend bool operator<=(const Version& a, const Version& b) {
        return !(b < a);
    }
    friend bool operator>=(const Version& a, const Version& b) {
        return !(a < b);
    }
};

Only == and < contain real logic, and the other four are built from them, like the Student struct in Lab 04.

Consider the optimized bubble_sort() from Lab 04:

template<typename Data>
void Sort::bubble_sort(Data *arr, const int len) {
    for (int i = 0; i < len; i++) {
        bool swapped = false;
        for (int j = 1; j < len - i; j++) {
            if (arr[j] < arr[j - 1]) {
                swap(arr, j, j - 1);
                swapped = true;
            }
        }
        if (!swapped) {
            break;
        }
    }
}
