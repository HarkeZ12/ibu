01Isn't bubble sort enough?

Last week we met bubble sort. In the lecture's measurements it needed 14 μs for 100 elements, 113 ms for 10,000 and 14 seconds for 100,000. It is quadratic, so ten times the elements take about a hundred times as long: a million elements would take around 23 minutes.

This week adds three more simple sorts: selection sort, insertion sort and Shell sort. Together with bubble sort they are the elementary sorts: short, easy to write, and all of them sort the array in place with Θ(1) extra memory.

Where this fitsBinary search from last week only works on a sorted array, so the natural next question is how we get one. The book spends four chapters on sorting: sorted data is useful (searching, grouping duplicates, ranking, merging), and sorting is a clean way to compare many algorithms on one exactly stated problem.

02What sorting is & what we count

Sorting rearranges N items into order. The order is decided by a key that belongs to each item and a rule for comparing two keys. When you sort integers, the key is the integer. When you sort students by grade, only the grade is compared; the name and everything else travel along without ever being looked at.

Every algorithm in the chapter compares whole elements with <. To sort a type of your own you define operator<: it takes two values and returns whether the first belongs before the second.

template<typename Data>
void bubble_sort(Data* arr, int len);   // all four sorts share this shape
voidIn placeThe function sorts the caller's array instead of producing a new one. That is why all four use Θ(1) extra space.
lenSeparate lengthAn array decays to a pointer, and a pointer carries no length.
<T>TemplateOne implementation sorts ints, strings and Student records.

Two costs: comparisons and exchanges

We count two operations: the comparison of two elements (is this one smaller?) and the exchange of two elements (swap them). They are not interchangeable. Comparing two integers is nearly free, while exchanging two large records means copying a lot of bytes. Every exchange goes through the same swap helper, so the counts are comparable between algorithms.

RememberAn algorithm can be good at one count and bad at the other. Selection sort is quadratic in comparisons but linear in exchanges.

03Stability

A sorting algorithm is stable if elements whose keys compare equal keep their original relative order: if an array has two 8s, the 8 that came first still comes first. An unstable algorithm makes no promise either way. It may keep the ties in order, reverse them or mix them up. Unstable does not mean "always reverses".

When does it matter? Not at all when the key is the whole element: every 8 is the same 8, so nobody can tell if two of them swapped. It matters when elements carry more than the key, and most of all when you sort the same data twice.

Sorting by several keys

Stability lets you sort by several keys with a simple single-key sort: sort by the least important key first, then by the next one, and so on. Each stable pass keeps the work of the passes before it.

The lecture's word countCount the words in "how much wood would woodchuck chuck if woodchuck could chuck wood". We want them by decreasing count, alphabetical when two counts are equal. So: sort by word first, then by count. A stable second sort keeps the alphabetical order inside each count. With selection sort (unstable) as the second sort, "if" and "much" ended up before "could" and "how".
Exam traps
  • Bubble and insertion sort are stable because they only swap neighbours on a strict <, so equal keys never cross. Change the comparison to <= and the output is still sorted but no longer stable.
  • Selection and Shell sort exchange distant elements. A long jump can carry an element past an equal key it was never compared with. That is the general shape of instability.
  • To test stability, sorting integers proves nothing. The book's tests sort 400 records that share 20 keys and check the ties.

04Adaptivity

A sort is adaptive if it takes less time on input that is already partly in order. A non-adaptive sort does the same work on shuffled, sorted and reversed input.

Adaptivity pays off because real data is often partly sorted: log files arrive in time order, exported tables come sorted by key, and a list sorted last week with a dozen new items is nearly sorted now. A non-adaptive sort has one advantage of its own: its running time is predictable.

Notation reminderThe lecture tables label the worst case with O, the average with Θ and the best with Ω. But the symbols and the cases are separate things: O is an upper bound, Ω a lower bound and Θ both, and each can describe any case. The book gives each case its tight Θ.

05Bubble sort, again

Walk along the array comparing each element with the one before it, and swap when they are out of order. The largest element gets carried along, so after one pass it sits at the end. Each pass leaves one more element in its final place.

for (int i = 0; i < len; i++) {
    bool swapped = false;
    for (int j = 1; j < len - i; j++) {   // last i are already home
        if (arr[j] < arr[j - 1]) { swap(arr, j, j - 1); swapped = true; }
    }
    if (!swapped) break;                     // a clean pass: sorted
}
CaseWhat happensCost
Worst: reversedevery pass swaps every pair: N(N−1)/2 comparisons and exchanges (124,750 at N = 500)Θ(N²)
Average: shuffledabout N(N−1)/4 inversions, half the worst caseΘ(N²)
Best: sortedone pass, N − 1 comparisons, 0 exchanges (499 at N = 500)Θ(N)
Best without the flagstill does every passΘ(N²)

Across all inputs bubble sort is O(N²) and Ω(N), but it is not Θ of anything: a single Θ would have to bound every input from both sides, and the best and worst cases are in different classes. It is stable (strict comparison of neighbours) and adaptive (that one boolean flag is its whole adaptivity).

So what is wrong with it?It moves elements one position per exchange, so an element that belongs k places away costs k exchanges. A large element flies to the end in one pass, but a small element at the end crawls left one place per pass: [2, 3, 4, 5, 6, 1] needs every pass. It also keeps re-scanning ordered regions, so it makes about twice as many comparisons as insertion sort for exactly the same exchanges.

06Selection sort

Selection sort works from the other end. In iteration i, assume the minimum is at position i, scan everything to its right, and remember the index min of the smallest element seen. Only after the scan, make one exchange: arr[i] with arr[min]. The minimum is "selected", hence the name. Position i is now final and never changes again.

for (int i = 0; i < len; i++) {
    int min = i;
    for (int j = i + 1; j < len; j++)
        if (arr[j] < arr[min]) min = j;   // only remembers, moves nothing
    swap(arr, min, i);                      // one exchange per i
}

What it costs

The comparison count does not depend on the data at all: (N−1) + (N−2) + … + 1 + 0 = N(N−1)/2. That is 28 for our eight elements and 19,900 for 200 elements, on sorted, reversed and shuffled input alike. There is no early exit, so best, average and worst are all Θ(N²), and they even agree on the exact count.

That makes selection sort the one algorithm in the chapter with a single unqualified Θ(N²). It is non-adaptive, and this is what non-adaptive looks like on paper.

The exchanges grow much more slowly: exactly N, one per value of i (the book's code swaps even when min == i). Bubble sort makes about 64 million exchanges on 16,000 shuffled elements; selection sort makes 16,000.

When few exchanges matterSorting large structs by value: a comparison reads one field, an exchange copies the whole record three times. Selection sort touches each record only about twice. Its running time is also very predictable. But those cases are narrow: on ordinary data it finished last of the four in the book's race.
Unstable: [3, 8, 3, 1]The first pass finds 1 at the end and exchanges it with position 0, which throws the first 3 over the second one. Output [1, 3, 3, 8] is sorted, but the two 3s have swapped order. Making it stable is possible (shift instead of exchange), but then the moves are no longer linear.

07Insertion sort

Insertion sort is how you sort a hand of playing cards: take the next card and push it left past every larger card until it fits. In the array, pushing left is a run of exchanges with the left neighbour. Stop at the first neighbour that is not larger, because everything further left is smaller still.

for (int i = 1; i < len; i++)
    for (int j = i; j > 0; j--) {
        if (arr[j] < arr[j - 1]) swap(arr, j, j - 1);
        else break;                      // landed: stop right now
    }
Two prefixes, two meaningsBoth selection and insertion sort grow a sorted prefix from the left. Selection sort's prefix holds the smallest elements of the whole array, each final. Insertion sort's prefix holds the first elements of the array, in order among themselves, and any of them can still be pushed right.

The break does the job of bubble sort's flag, and does it better: bubble sort has to finish a whole pass before it learns that the pass was unnecessary, while insertion sort stops the moment the element lands.

CaseWhat happensCost
Worst: reversedevery element travels to the front: N(N−1)/2 comparisons and exchangesΘ(N²)
Average: shuffledeach element moves about half as far: ≈ N²/4 exchangesΘ(N²)
Best: sortedbreak fires on the first comparison every time: N − 1 comparisons, 0 exchangesΘ(N)

Like bubble sort, it is O(N²) and Ω(N) with no single Θ. It is stable and strongly adaptive.

Two common improvements

Shift instead of swapSave the element, move the larger ones one place right, write it into the gap once. An exchange writes two elements, so this roughly halves the writes.
Binary insertion sortThe prefix is sorted, so binary search finds the spot in about lg N comparisons. Comparisons drop to about N log N, but on an array the elements still have to move, so it stays Θ(N²).
Book vs lectureIn the lecture's measurements insertion sort (7 s for 100,000) landed between selection (4 s) and bubble sort (14 s). In the book's experiment it was the fastest of the three quadratic sorts, about four times faster than selection sort. Results depend on the data, the language and the implementation.

08Inversions

An inversion is a pair of positions i < j whose elements are in the wrong order: arr[j] < arr[i]. A sorted array has 0. A reversed array has N(N−1)/2, the maximum. A shuffled array has about half of that.

insertion sort: exchanges = I  ·  I ≤ comparisons ≤ I + N − 1

Why exactly one per exchange? An adjacent exchange fixes the order of the two swapped elements and changes nothing else: every other element is left of both or right of both, so its relation to each of them stays the same. The array starts with I inversions and ends with none. For comparisons, each pass makes one per exchange plus at most one more when the break fires, and there are N − 1 passes.

  • An array with a linear number of inversions is sorted in linear time. That is what "partly sorted" means precisely.
  • Bubble sort also exchanges only neighbours, so bubble and insertion sort make identical exchange counts on every input. At 16,000 elements: 64,389,560 each. Bubble sort makes about twice as many comparisons.
  • An array of N equal elements has 0 inversions: insertion sort makes N − 1 comparisons and no exchanges.
Insertion sort inside bigger algorithmsIts short inner loop makes it great for small subarrays, and its inversion-based cost makes it great for extending short sorted runs. Real libraries use it to finish small or nearly sorted pieces inside faster sorts (next chapter, and Timsort).

09Shell sort

Bubble and insertion sort move an element one position per exchange, so they have to remove a quadratic number of inversions one at a time. Donald Shell (1959) asked: can we use distant exchanges without repeating selection sort's minimum searches?

h-sortingAn array is h-sorted when every h-th element, taken from any starting position, is in order. h-sorting is insertion sort over elements h apart instead of 1 apart.

A large h moves an element a long way with one exchange. It does not finish the job, but it cannot make things worse, and it leaves the array much closer to sorted. Shell sort h-sorts for a decreasing sequence of h ending at 1. The last pass is plain insertion sort, so the result is always sorted, and by then the array is nearly in order, exactly where insertion sort is fastest.

int h = 1;
while (h < len / 3) h = 3 * h + 1;         // 1, 4, 13, 40, 121, ...
while (h >= 1) {
    for (int i = h; i < len; i++)
        for (int j = i; j >= h; j -= h) {
            if (arr[j] < arr[j - h]) swap(arr, j, j - h);
            else break;
        }
    h = h / 3;
}

Hold the inner loops next to insertion sort: the same loops with every 1 replaced by h. Insertion sort is Shell sort with the single increment 1.

10Choosing the increments

The increment sequence matters more than anything else in the algorithm.

Shell's halvingN/2, N/4, …, 1. It works, but not very well: the increments share factors, so passes keep re-sorting the same subsequences.
Knuth's 3h + 11, 4, 13, 40, 121, 364, … The code climbs it while h < len / 3, then divides by 3 after each pass.

Try 8 (h = 4, 1), 1,000 (364 … 1, six passes) and 100,000 (eleven passes, from 88,573 down to 1). Watch the boundary: 14 elements start at h = 4, but 15 start at h = 13, because len / 3 is integer division.

Why eleven passes are cheapEvery pass is cheap for a different reason. Early passes: a large h leaves few elements in each subsequence. Middle passes: the array is already partly ordered. Last pass: insertion sort is linear on nearly sorted data.

11What Shell sort costs

Shell sort is hard to analyse, because each pass changes the input of the next one.

WorstΘ(N3/2) = O(N√N)upper bound proved; Vaughan Pratt (1971 thesis) showed some inputs really take that long. A reversed array is not the worst case: long early passes fix most of it.
Best: sortedΘ(N log N)nothing moves, but each of the ≈ log N passes still scans the array

Across all inputs: O(N3/2) and Ω(N log N), so like bubble and insertion sort it has no single Θ. Unlike them, its average case is unknown.

An open problem you can hold in your handShell sort is fifteen lines long, has no randomness, and its behaviour on any given input is completely determined. Yet nobody can say how many comparisons it makes on average. After an h-sort, the input to the next pass is no longer random; it inherits a structure nobody has described precisely enough to count. The best increment sequences were found by experiment, not derived.
Adaptive but unstableShell sort is adaptive (later passes work on partly ordered data). It is unstable for the same reason selection sort is: with [1, 0, 0, 0, 0, 0] the code uses h = 4, exchanges positions 4 and 0, and that 0 jumps over three other 0s it was never compared with.

The selection sort puzzleOn an already sorted array of 64,000 elements, bubble, insertion and Shell sort finish in under 0.2 ms. Selection sort takes 0.69 s, under a third of its shuffled time. 15Key takeaways

  • A stable sort keeps equal keys in their original order; an unstable one makes no promise. For several keys, sort by the least important key first.
  • An adaptive sort is faster on partly ordered input, which real data often is.
  • Comparisons read, exchanges write; an algorithm can be cheap in one and expensive in the other.
  • Bubble: largest to the end each pass; the swapped flag is its whole adaptivity; Θ(N) best, Θ(N²) average and worst.
  • Selection: exactly N(N−1)/2 comparisons and exactly N exchanges on every input; the only single Θ(N²); unstable and non-adaptive.
  • Insertion: one exchange per inversion, comparisons between I and I + N − 1; stable and adaptive; used inside faster sorts.
  • Bubble = insertion in exchanges on every input; bubble makes about twice the comparisons.
  • Shell (Shell, 1959): h-sort for decreasing h ending at 1. With Knuth's 3h + 1 (1, 4, 13, 40, …): best Θ(N log N), worst Θ(N3/2), average unknown. Adaptive, unstable.
  • All four sort in place with Θ(1) extra space. At ten million elements Shell sort takes under two seconds; the others would take hours.

Next time you sort a hand of cards, you will know you are running insertion sort.
